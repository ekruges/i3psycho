i3psycho User Guide
===================

i3psycho is i3 with floating-first behavior: macOS-grade window management on
top of an unmodified i3 core. It is a small patch series (8 patches) on
upstream i3 plus a companion IPC daemon, `psychod`. Everything you know about
i3 still applies: the config language, the IPC protocol, workspaces, marks,
the scratchpad, i3bar, i3status, and your muscle memory.

This guide covers installation, daily use, every new binding and action,
configuration, the exact list of behavior differences from stock i3, and
troubleshooting.

1. Installation
---------------

Arch Linux:

```
git clone https://github.com/ekruges/i3psycho
cd i3psycho/packaging && ./mkpkgfiles.sh
makepkg -si
```

The package provides and conflicts with `i3-wm` (the i3-gaps model): the
patched binary is a drop-in `i3`. Your display manager gets an "i3psycho"
session entry. `psychod` lands in `/usr/bin`.

Any distro, manual:

```
git clone https://github.com/ekruges/i3psycho && cd i3psycho
./packaging/build-i3psycho.sh          # clones upstream i3, applies patches/, builds
sudo ninja -C i3-build/build install   # installs the patched i3
sudo install -m755 psychod/psychod.py /usr/local/bin/psychod
```

Runtime dependencies for psychod: `python3`, `python3-i3ipc`, `xdotool`
(hot corners only).

2. Choose your entry path
-------------------------

Existing i3 user (recommended): add one line to the BOTTOM of your i3 config:

```
include /usr/share/i3psycho/psycho.conf
```

Then restart i3 ($mod+Shift+r) and run:

```
i3psycho-doctor
```

That adds float-by-default, the psychod bindings, and the daemon launch.
Your colors, bar, and existing binds are untouched. Delete the line to go
back to stock behavior.

Three things about that sequence are load-bearing, and each one has its own
failure that looks like "i3psycho is broken":

- **Bottom, not top.** i3 keeps the LAST binding for a key. An include at the
  top of your config gets silently overridden by every bind below it, and
  none of the psycho keys do anything.
- **Restart, not reload.** i3 runs `exec_always` on start and restart only;
  `reload` re-reads the config and never touches autostarts. Reload after
  adding the include and psychod does not start, so every binding is a no-op.
- **Run the doctor.** `i3psycho-doctor` inspects the live session and reports
  what is actually wrong, with the line to add for each: whether you are on
  the patched binary or still running the old one, whether psychod is up,
  which of your binds i3psycho took (or which of its binds you overrode),
  `for_window` rules that fight the cascade for window position, windows with
  no titlebar to draw buttons in, and whether your bar can show the chips.

Things it will tell you about, worth knowing in advance:

- i3psycho claims `$mod+Left/Right/Up/Down` for snapping. i3's own default
  config binds those to focus. Keep focus on `$mod+h/j/k/l`, or move snapping
  to `$mod+Ctrl+arrows`.
- If a window opens with no titlebar it has no buttons, because the buttons
  are drawn in the titlebar. Applications suppress decoration through
  `_MOTIF_WM_HINTS` and i3 honors it — terminals do this most often (in
  xfce4-terminal it is "Display borders around new windows"). psycho.conf
  ships `for_window [class=".*"] border normal 2` to override it.
- If you have `for_window ... move position center` rules, drop them for
  normal windows. They run in the same batch as the cascade and the last
  write wins, so windows land in random spots. Keep them for dialogs, which
  psychod deliberately skips.
- Chips for minimized windows are drawn by i3bar. On polybar, install
  `contrib/psycho-chips-polybar.py` (instructions are in its docstring).

Fresh install: use the standalone config:

```
cp /usr/share/i3psycho/psycho.config ~/.config/i3/config
```

It is a complete, commented i3 config: the psycho layer plus the standard
i3 survival kit (terminal, dmenu, workspaces, reload/restart/exit).

3. Daily use
------------

| Input | Effect |
|---|---|
| Drag titlebar | Move window (stock i3 behavior) |
| Drag to screen edge | Live snap preview (solid blue); drop to snap. Left/right = halves, top = maximize, corners = quarters |
| `×` titlebar button | Close window |
| `−` titlebar button | Iconify (minimize) to the scratchpad, geometry remembered |
| `+` titlebar button | Fullscreen toggle |
| Double-click titlebar | Fullscreen toggle |
| App's own minimize button | Same as `−` (WM_CHANGE_STATE Iconic is honored) |
| Click chip in bar | Restore that minimized window in place |
| Hot corner top-left | Expose |
| Hot corner bottom-right | Show desktop |
| `$mod+Left / Right / Up / Down` | Snap left half / right half / maximize / center |
| `$mod+Ctrl+1..4` | Snap to quarter (TL, TR, BL, BR) |
| `$mod+m` / `$mod+Shift+m` | Minimize / restore most recent |
| `$mod+Tab` | Cycle windows, most-recent-first; pause 1.2s to commit |
| `$mod+e` | Expose: all floats in a grid; toggle, click, or cycle to exit |
| `$mod+Shift+d` | Show desktop toggle |
| `$mod+t` | Toggle this window back to tiling. Everything i3 does with tiles still works |

New windows cascade from the top-left like macOS instead of stacking dead
center. Dialogs, splash screens, and notifications are left where the
application puts them.

4. psychod reference
--------------------

psychod is a pure IPC client. It never touches X directly (except the
optional hot-corner pointer poll via xdotool), so it can never crash the
window manager. If it dies, i3 keeps running; `exec_always` restarts it on
the next i3 *restart*, and a `flock` guard prevents duplicates. It
reconnects automatically when i3 restarts in place.

Note the difference between restart and reload, because it is easy to lose
an hour to: i3 drains its `exec_always` list only when it starts or restarts
(`$mod+Shift+r`). `reload` re-reads the config and does not run autostarts at
all, so after editing psycho.conf a reload applies your new bindings while
leaving the old psychod process running with the old flags -- or leaving no
psychod running at all, if it was not up before. Restart, don't reload.

Actions:

Trigger from a keybinding (`bindsym ... nop psycho:<action>`) or from
scripts (`i3-msg -t send_tick psycho:<action>`):

| Action | Meaning |
|---|---|
| `psycho:snap:left\|right\|max\|center\|tl\|tr\|bl\|br` | Snap focused window to exact workarea region |
| `psycho:min` | Minimize focused window, remember geometry |
| `psycho:restore` | Restore most recently minimized |
| `psycho:restore:<con_id>` | Restore a specific window (used by the bar chips) |
| `psycho:cycle` | Walk the MRU window stack |
| `psycho:expose` | Toggle the expose grid on the focused workspace |
| `psycho:showdesktop` | Toggle all floats on the workspace to/from the scratchpad |

Flags:

| Flag | Default | Meaning |
|---|---|---|
| `--cascade-step N` | 30 | px offset between cascaded spawns |
| `--edge-margin N` | 25 | px beyond the workarea edge that triggers poll-based drop-snap |
| `--drop-debounce S` | 0.25 | seconds a moved window must rest before snapping |
| `--hot-corners SPEC` | `tl=expose,br=showdesktop` | `corner=action` pairs, or `none` |
| `--hot-corner-size N` | 8 | px square at each corner that arms it; raise it on HiDPI |
| `--hot-corner-delay S` | 0.5 | seconds the pointer must rest there |
| `--auto-hide-bars EDGES` | `none` | `top`, `bottom`, `top,bottom`: bar hides until that edge is hovered |
| `--bar-class REGEX` | `polybar\|i3bar` | which bars auto-hide applies to |
| `--bar-slide-ms N` | 140 | slide duration; 0 disables the animation |

Auto-hiding bars:

`--auto-hide-bars bottom` parks the bar off-screen and slides it back when
the pointer touches that edge; `top` does the same downward. The bar must be
override-redirect, or i3 owns its placement and reverts every move: polybar
`override-redirect = true`, i3bar `mode hide`. Such a bar reserves no space,
so windows get the whole output and the bar floats over them.

The bar dock:

Patch 0005 puts the chips in i3bar itself, so there is nothing to configure
and no wrapper to install -- keep your existing `status_command`. i3bar reads
the minimized set over IPC and draws one clickable chip per window, left of
the statusline. Set `psycho_chips no` to turn them off.

Earlier drafts of this guide told you to set `status_command psychod-status`.
No such program was ever shipped in this repo -- following that made i3bar
exec a missing binary and left you with no statusline at all. Patch 0005
replaced that design; the wrapper is gone.

Other bars (polybar, waybar) do not read i3's chip protocol, so they need a
module of their own: subscribe to `window` and `tick` events, list the leaves
of `__i3_scratch`, and emit `i3-msg -t send_tick psycho:restore:<con_id>` as
each chip's click action.

5. Behavior differences from stock i3
-------------------------------------

Complete list. Everything not listed behaves exactly like i3.

1. Floating windows get titlebar buttons (close / iconify / maximize)
   drawn in your titlebar text color. Tiled windows are untouched.
2. Double-clicking a floating titlebar toggles fullscreen (stock i3:
   starts a drag with no click action).
3. Dragging a floating window to a workarea edge shows a snap preview
   and snaps on drop (stock i3: plain move).
4. `WM_CHANGE_STATE` Iconic requests are honored and move the window to
   the scratchpad. Stock i3 rejects them (in-app minimize buttons do
   nothing there). Unmanaged windows still get the stock reject.
5. Scratchpad windows carry `_NET_WM_STATE_HIDDEN` and ICCCM
   `WM_STATE` Iconic while hidden (stock i3: WITHDRAWN and no hidden
   state). Pagers and taskbars can tell minimized windows apart.
6. Floating repositions emit `window::move` IPC events (stock i3 emits
   none; this one is a candidate upstream patch).
7. With the shipped config: new windows float by default via
   `for_window [tiling] floating enable` — plain config, remove the line
   for stock behavior.

Vanilla i3 configs run unmodified. The IPC protocol is unchanged and only
extended by events that did not fire before.

6. Performance notes
--------------------

- Build with `--buildtype=release` (the build script and PKGBUILD do).
  Meson's default is a debug build and it is visibly slower.
- `dist/picom.conf` is an intentionally invisible compositor config:
  vsync only, every eye-candy feature off. Use it if you see tearing
  during drags; skip it entirely on a well-behaved driver.
- Measured end-to-end action latency (tick to geometry applied) in a
  2-core build container: 1.9 ms mean, 3.0 ms max.

Config directives (patched i3 only; stock i3 refuses to parse them):

| Directive | Default | Meaning |
|---|---|---|
| `psycho_titlebar_buttons` | yes | close / iconify / maximize in the titlebar |
| `psycho_double_click_titlebar` | yes | double-click toggles fullscreen |
| `psycho_snap_edges` | yes | live snap preview while dragging |
| `psycho_snap_margin N` | 10 | px from the edge that shows the preview |
| `psycho_genie_duration N` | 140 | minimize/restore ghost, ms; 0 disables |
| `psycho_chips` | yes | minimized-window chips in i3bar |
| `psycho_exact_size` | yes | snapped windows fill their region exactly |
| `psycho_drag_threshold N` | 1 | px before a drag starts; 0 tracks immediately |

7. Troubleshooting
------------------

- Something ignores my keybind: psychod not running? Check
  `pgrep -af psychod`, and `i3-msg -t send_tick psycho:snap:left` to test
  the pipeline without keybindings.
- psychod logs: it writes to stderr, which lands in i3's log. Run
  `i3 --moreversion` to confirm you are on the patched binary, and use
  `DISPLAY=:0 psychod` in a terminal to watch it live.
- Windows spawn centered, not cascaded: the daemon is not connected;
  see above.
- Windows land in *random* spots, some cascaded and some not: you have a
  `for_window ... move position center` (or `move absolute position`) rule
  of your own. Those run in the same assignment batch as `floating enable`,
  after the cascade has already placed the window, so whichever fires last
  wins. Drop the centering rule for normal windows and let the cascade own
  position; keep it for dialogs, which psychod deliberately skips.
- A window snapped with a small gap at the bottom: its size hints (terminal
  character cells) round the size down. `psycho_exact_size yes` (the default)
  ignores the increment so the region is filled; set it to no to honor hints
  like stock i3 does.
- Dragging feels laggy or jumps when it starts: stock i3 waits for
  logical_px(15) of movement first, which is a 30px dead zone at Xft.dpi 192.
  Lower `psycho_drag_threshold`, or set it to 0 to track from the first
  motion event.
- Bug reports: include `i3 --moreversion`, your config, and
  `/tmp/psychod-*.lock` ownership. The i3 debug log workflow
  (`i3-dump-log`) works unchanged.

8. FAQ
------

Is this a fork? An 8-patch series on a pinned upstream i3 release (4.25.1),
rebased per release, plus a daemon that any stock i3 can also run (with
graceful degradation). The i3-gaps model.

Wayland? No. This is X11, like i3. A Wayland i3psycho would be a sway
patch series, which is a different project.

Can I keep tiling? Yes. `$mod+t` returns any window to the tree, and
every tiling feature is intact. i3psycho is a superset.

Why is the UI so plain? On purpose. The blue titlebar is sacred, and
there are no shadows, no rounded corners, no animations: that is the i3
aesthetic, and it is frozen by decree of the project.
